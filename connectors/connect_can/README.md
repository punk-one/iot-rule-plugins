# SocketCAN Connector

```json
{"interface":"can0","read_ids":[{"id":"0x123"},{"id":"0x123","extended":true}],"write_ids":[{"id":"0x321"}],"can_fd":true,"include_error_frames":true,"receive_own_messages":false,"allow_write":false,"allow_rtr_write":false,"timeout_ms":1000}
```

Resource creation is offline and reserves an interface name within this provider process (not across independent engines or external CAN tools). At most8 resources,256 distinct IDs/read or write list and32 Source subscriptions/resource. IDs are decimal without leading zeroes or explicit0x hex; standard11-bit and extended29-bit identifiers remain different even for the same numeric value. Write permission requires explicit IDs and allow_write. Empty read IDs are allowed only for an explicitly configured write resource. Arbitrary all-interface binding and range masks are not offered.

One raw socket/resource is opened on first actual read/write demand. Continuous Sources share that socket and its reader; writes serialize at the resource gate while the reader may continue. Last Source removal closes it unless a write is active; standalone writes close at completion. Stop/delete cancels I/O and closes/join readers; fatal socket errors retire the session, with no background reopen. Resource remembers the first interface index and rejects replacement under the same name until explicitly recreated. Different local resources cannot silently double-own the same name. Other applications may legitimately open their own SocketCAN sockets.

Classical frames0..8bytes, extended identifiers, explicit RTR0..8, CAN FD canonical lengths0..8/12/16/20/24/32/48/64, BRS/ESI and optional received error frames. No silent FD padding. can_fd=true needs kernel support and interface MTU>=72. Payload byte order belongs to the ECU protocol, not SocketCAN. Error-frame transmission is forbidden. receive_own_messages=false avoids accidentally feeding the engine's own writes back into a rule.

OpenStream target `frames`, payload `{ids:[{id:"0x123",extended:false}],include_errors:false,include_remote:false}`. IDs must be a subset of resource read_ids; errors need resource permission. Initial credit1..64, queue exactly64 and fail_session policy. Per-consumer pending/credit window is bounded64. Slow consumer overflow fails that consumer and releases its queue; others continue. ACK releases one actually delivered frame's credit and rejects duplicate IDs. NACK can discard but cannot requeue a best-effort bus frame. Generation-unique stream IDs prevent late closes from retiring a new stream.

Receive returns copied frame bytes, canonical ID/format flags, RTR/raw DLC, error status, receive timestamp and kernel-drop counters as strings. Kernel RX/TX socket buffers are bounded; SO_RXQ_OVFL is reported without replacing missing frames with fabricated values. These limits do not make CAN durable: bus and consumer overflows lose data explicitly.

Write target `send`: `{frame:{id:"0x321",extended:false,fd:false,remote:false,data:"<base64>"},expires_at:<UTC milliseconds>}`. Checks format/allowlist, FD/RTR permissions and expiry before device access; max future horizon60s, finite50..5000ms total deadline includes waiting. Native write rechecks wall-clock expiry immediately before socket acceptance. No transparent retry. Positive response is exactly `{queued:true,scope:"local_socket"}`; never a business/device-completion ACK. Stats target `stats` and Probe do not open a socket; idle configured state is distinguished from bound interface and errors, and does not prove an ECU is reachable.

Independent version1.0.0 development-preview artifact, SDK v1.0.0 unchanged, Go1.27.4 security baseline. Linux amd64/arm64; pure Go x/sys, no CGO/vendor runtime. Configure and authorize the host CAN interface outside the plugin. The engine/plugin does not load arbitrary drivers, change bitrate, bring physical interfaces up/down or broadcast discovery commands. A successful raw-socket write is local kernel acceptance, not an ECU acknowledgment or completed physical action.

Native tests use Linux SocketCAN and vcan in a newly created user/network namespace. No physical ECU is accessed. Fixed-vector/limits/race tests, two-Sources sharing one resource, stop isolation and command-guard preventing repeated physical writes have local evidence; ARM runtime, real controller/ECU, error recovery on a real bus and high-load/long-run acceptance remain pending. No CANopen, J1939, ISO-TP, DBC import, UDS or proprietary USB API support is implied; raw frames can feed decode-binary with an explicit field/byte-order configuration.
