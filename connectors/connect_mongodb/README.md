# MongoDB Connector

```json
{"hosts":["mongo.example.invalid:27017"],"database":"telemetry","collections":["events"],"username":"collector","password":"<protected-secret>","auth_source":"admin","tls":true,"direct":true,"timeout_ms":5000,"max_rows":1000,"allow_write":false}
```

Resource creation is offline. First operation establishes one shared native client/pool; max 2 pooled connections, 1 connecting at a time, 60 s idle retention, driver topology monitoring, serialized operations per resource and at most 8 resources. This is a database pool, not the PLC demand-session policy. Stop cancels operations and disconnects the pool. No client-command retry (retryReads/retryWrites=false); Source controls polling backoff. Driver monitoring is not a transparent replay of writes.

System/optional ca_pem roots, hostname validation and TLS >=1.2 are required. No skip-verify. SCRAM-SHA-256 credentials are separate fields, not URLs. Literal loopback may explicitly disable TLS in direct test mode only. direct=true requires one host; direct=false enables normal server discovery and must be allowed by the deployment network policy. Configure replica_set when applicable. Do not expose arbitrary untrusted database servers to this client.

Read target `find`: `{collection:"events",filter:{"device":"machine-001"},sort:"_id",descending:false,limit:100}`. Only configured collections, bounded field paths and comparison/and/or/not/in/exists filter operators; no $where/$function/$expr/regex or duplicate filter keys. Filter <=64 KiB, JSON nesting <=24, 65536 tokens; BSON filter <=16 levels/4096 items. Canonical Extended JSON scalar literals are supported. Plain integers above 2^53-1 are rejected: use decimal strings or explicit `$numberLong`/`$numberDecimal` literals. This avoids silent uint64-to-double loss.

Query fetches at most limit+1 (batch size <=16). More rows than limit fail with no partial response; narrow the query. Each raw/canonical document <=1 MiB, total emitted document bytes <=4 MiB, max1000 rows. The native driver still negotiates and allocates wire batches before these application limits; these are returned-data bounds, not a sandbox for malicious MongoDB servers. Cursor close and the entire operation have finite deadlines. Output: `{documents:[<canonical Extended JSON objects>],count:N}`. BSON int64, Decimal128, dates, ObjectIDs and binary remain explicit wrappers, rather than lossy JavaScript numbers.

Write target `insert_event`: `{collection:"events",event_id:"stable-id",payload:{...}}`. Requires allow_write; immutable stored document is `{_id:event_id,sha256:SHA256(original-payload-JSON-bytes),payload:<BSON document>}`. Single insert requests majority write concern. Duplicate ID is accepted only after majority read finds the same digest; different bytes fail. Unique `_id` handles competing writers without replace/update races. Unknown write/commit outcomes never produce a receipt. Output `{committed:true,event_id:"stable-id",duplicate:false}`. Same stable ID and exact payload bytes are required for safe replay; semantically equivalent JSON with different bytes intentionally conflicts.

These are independent development-preview modules, version 1.0.0, consuming SDK v1.0.0. Native MongoDB Go driver v2.10.0 is Apache-2.0, pure Go (no libmongoc/CGO/encryption helper), optional artifact only; preserve its LICENSE/NOTICE and transitive notices in the SBOM. No MongoDB server binary is redistributed. Tests use the real driver against a local OP_QUERY/OP_MSG wire fixture, plus node ownership/limits/ACK tests. This is not a real MongoDB replica-set, TLS/SCRAM or failure-election acceptance test.

No aggregation, arbitrary command execution, updates/deletes, multi-document transactions, GridFS, change streams or resume-token claims. Use dedicated database permissions and indexes; the query subset is not a tenant isolation boundary. A majority receipt is a MongoDB single-document database acknowledgment, not device execution or downstream business completion.
