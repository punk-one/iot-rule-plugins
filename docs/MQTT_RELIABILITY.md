# MQTT session and queue reliability

`connect-mqtt` supports MQTT 3.1.1 `clean_session` (default true, preserving the old behavior). False requests a broker persistent session with a stable client identity; the generated identity remains scoped to Engine instance and resource, or operators can supply client_id. Configure broker offline queue/retention limits separately. This option does not enable MQTT5 expiry or create business commit confirmation.

Connection recovery is driven by real reads/writes; an existing stream receive now verifies/restores the physical client instead of appearing idle forever after disconnect. Source intents register before dialing. A bounded pre-routing queue retains persistent-session packets that arrive before later Sources open. Only missing/changed subscriptions are renewed, avoiding retained-message loops. Subscription RPCs have finite waits outside resource.mu. Stream IDs identify generations, so a stale close cannot retire a replacement stream. Closed/overflowed streams return an error so Source can recover.

Limits: payload <=256 KiB, <=32 streams/legacy bindings per resource, <=64 filters per request; credits <=1024, buffered messages <=4096 and deliver batch <=64. Resident queue leases include pending messages: 4 MiB/session, 8 MiB/resource and 64 MiB/plugin process (payload/metadata charge). ACK/NACK/close release memory; duplicate/unknown ACKs cannot mint credits. In-flight deliveries are never evicted by drop_oldest. Queue policies and native MQTT decoder/OS buffers have distinct limits; the budgets do not claim to cap every library/OS allocation. Oversize/resource overflow is counted, and Source transports overflow observations in Metadata without changing a signed business payload.

Broker PUBACK, local stream credit ACK, Engine durable dispatch, database commit and device completion are separate. Paho broker protocol ACK is not delayed until a business transaction commits. Process memory queues/pre-routing are not durable across a crash; applications requiring end-to-end recovery use the signed application receipt + persistent buffer/transaction receipt chain. Deliberate Source stop unsubscribes its topics when no consumer remains; decommission persistent broker sessions according to broker policy.

Independent Mosquitto 2.0.18 tests verify offline QoS1 queue recovery, early cross-Source packets, broker restart using an existing stream, single-Source stop isolation, and memory lease cleanup. The daemon is private loopback, extracted only into the test directory. These are not production EMQX/TLS/QoS2 or long-run acceptance. The two real Engine business receipt test separately checks transaction-before-receipt and loss/replay deduplication.
