# iot-rule-plugins 全量复审

- 审计日期：2026-09-09
- 范围：23 个官方插件、独立 module、manifest、SDK v1 契约、构建与发布门禁
- 审计目标：可靠性、稳定性、可扩展性
- 环境限制：本轮没有连接真实 MQTT、Redis、PostgreSQL、TimescaleDB、TDengine、S7 PLC 或 FANUC 设备做长稳测试

## 结论

23 个官方插件均为独立目录、独立 `go.mod`、独立 `plugin.json` 和独立构建产物，插件之间
不存在源码 import；公共运行时边界仍只有 `iot-rule-plugin-sdk v1.0.0`。本轮逐模块执行
`go test -race`、`go vet` 和 `go build`，23/23 通过，FANUC 默认 stub 也通过。

| 维度 | 评级 | 结论 |
| --- | --- | --- |
| 可靠性 | B+ | 生命周期与竞态门禁完整；真实服务故障注入和 JS 内存上限仍需发布环境补齐 |
| 稳定性 | B+ | 23 个模块全部固定 v1.0.0 并可独立构建；仍缺 24h/72h 真实设备长稳数据 |
| 可扩展性 | A- | 插件间无共享源码，manifest 和 SDK 边界清晰；协议能力可独立演进 |

## 本轮整改

### 通用 Redis 关系映射

删除业务化的 `iot-mes-mapping`，替换为 `redis-relationship-mapping`：

- 字段路径相对于 `event.payload`，不再出现 MES、产品或设备领域假设；
- 每个映射可独立选择 Redis Hash，也可继承 `default_hash_key`；
- 查询从 `HGETALL` 改为 `HGET`，不再为单字段映射拉取整个 Hash；
- 未匹配策略固定为 `skip`、`default`、`error`；
- 输出基于 `Event.Clone()`，不会修改上游事件。

迁移规则：规则节点插件 ID 从 `iot-mes-mapping` 改为
`redis-relationship-mapping`；`src_field/dest_field/hash_key` 分别迁移为
`source_path/target_path/default_hash_key`。

### JavaScript Transform

新增独立插件 `javascript-transform`。脚本必须定义 `function main(input)`；引擎以 JSON 兼容的
`input` 调用该主函数，并提供 `console.log/info/warn/error` 写入规则日志。主函数返回：

```json
{
  "payload": {},
  "metadata": {},
  "timestamp_ms": 0
}
```

其中 `payload` 必填，后两项可选；返回 `null`/`undefined` 表示丢弃事件。每条事件创建
新的 JavaScript Runtime，默认 50ms、最大 1000ms，未暴露 `require`、npm、文件、网络、
环境变量或宿主进程对象。编译后的程序只读复用，Runtime 不跨事件共享。管理页面提供 520px
代码编辑器、完整标准示例和代码书写位置说明。第三方库不允许运行时在线安装，应固定版本后
封装为独立、签名并经过 SBOM/许可证检查的插件。

## Manifest 结论

每个插件都必须有独立 `plugin.json`。manifest 是引擎和发布流水线在不执行插件代码时可读取
的信任边界，至少固定 ID、版本、类型、SDK 主版本和 module。仓库测试会校验：

- 23 个 manifest ID 唯一；
- 全部版本为 `1.0.0`，SDK 为 `iot-rule-plugin-sdk@v1.0.0`；
- manifest module 与插件自己的 `go.mod` 一致；
- manifest 身份与 `PluginInfo()` 一致；
- Connector 使用 `ServeConnector`，其余插件使用 `ServeFactory`；
- 禁止 import 其他插件目录。

## 剩余风险与后续门禁

| 编号 | 等级 | 风险 | 建议门禁 |
| --- | --- | --- | --- |
| PLG-101 | P1 | JavaScript 引擎可中断 CPU 循环，但没有单 Runtime 内存硬上限；恶意脚本可能使 JS 插件进程 OOM | 规则脚本仅管理员可编辑；生产用 cgroup/容器限制插件进程内存；补 OOM 恢复演练 |
| PLG-102 | P1 | 本轮没有真实协议服务和 PLC/FANUC 长稳测试 | 发布前执行 24h 冒烟和 72h 长稳，覆盖断网、重启、超时、重复投递和部分失败 |
| PLG-103 | P2 | 多个 Redis 映射目前按映射逐次 HGET，高映射数会线性增加往返 | 后续为 Connector 增加 `hash_mget`，按 Hash 分组批量查询 |
| PLG-104 | P2 | SQL/Redis 请求由 deadline 收敛，但运行中请求没有统一继承节点 Stop context | SDK v1 保持兼容，v1 扩展可选取消令牌；当前必须确保每个调用都有有限 timeout |

Goja 官方说明确认，编译后的 Program 可在多个 Runtime 运行，`Interrupt` 可中断 JavaScript
执行，但不能中断原生 Go 函数。因此本插件不向脚本注入任何原生 I/O 函数：
https://github.com/dop251/goja
