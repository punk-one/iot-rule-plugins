# 官方插件审计与修复记录

审计日期为 2026-11-21。基线为 `7535bb4`，覆盖 120 个独立插件的目录、依赖隔离、清单、构建与测试入口。人工复核重点为 MQTT、PostgreSQL、TimescaleDB、TDengine 的连接、接收、确认和写入路径，以及发布脚本。型号、固件和真实设备协议表现仍按插件单独验收。SDK 继续使用 v1.0.0。

| 优先级 | 发现 | 本次修复与验证 |
| --- | --- | --- |
| P1 | PostgreSQL、TimescaleDB 和 TDengine Sink 直接拼接运行时表名与字段名。非法标识符可使遥测生成无法执行的 SQL。TDengine 的调试日志还会记录携带遥测值的完整语句。 | 在连接 I/O 前校验表名、子表名和字段名，拒绝大小写折叠后重复的字段。TDengine 集中转义字符串并移除完整 SQL 调试日志。回归测试验证非法标识符不会触达 Connector。 |
| P1 | 三类 SQL Sink 在批量写失败后逐条重做，响应丢失时可能重复写入已经提交的记录。定时刷新遇到一张表失败会丢弃后续尚未尝试的表。定时刷新和阈值刷新同时访问自动建列缓存。 | 无法得知提交状态时报告错误，停止自动逐条重做。TDengine 子表路径在发送前选择逐条模式。刷新遍历所有表后汇总错误，并加锁保护自动建列缓存。回归测试模拟写入响应失败，确认每表只尝试一次且其他表继续刷新。 |
| P1 | PostgreSQL 和 TimescaleDB Connector 使用 `float64` 解码 JSON 数字实参。超过安全整数范围的计数和长小数可能被舍入。 | 保留数值字面量直到数据库绑定。两套 Connector 用隔离的 PostgreSQL 16.15 实测 BIGINT `9007199254740993` 和 NUMERIC `1.234567890123456789` 的事务写入及参数查找。 |
| P2 | 删除或替换尚未建池的 SQL Connector 资源后，已持有旧指针的请求仍能初始化旧池。关闭连接池时持有 Connector 的共享锁。 | 检查资源代际，将旧池从当前资源表移除后再关闭。回归测试覆盖更换和删除后的旧代际，适用于三套 SQL Connector。 |
| P2 | MQTT 返回消息与等待确认队列共用切片和元数据，重投会修改已返回的对象。接收批量可越过协商上限，关闭通知只唤醒一个等待者，旧轮询模式可逐次积累超过限制的主题。 | 返回独立负载和元数据，强制协商批量并限制长轮询为 30 秒。关闭时唤醒所有接收者并释放资源预留，每个旧轮询绑定最多 64 个主题。回归测试覆盖重投隔离、关闭和上限，真实 Mosquitto 验证持久会话与重连。 |

连接器 `connect-postgres`、`connect-timescaledb`、`connect-tdengine`，以及 `sink-relational-postgres`、`sink-timeseries-timescaledb`、`sink-timeseries-tdengine` 升至 1.0.2。`connect-mqtt` 升至 1.0.4。清单与代码版本一致。应使用普通字母、数字和下划线构成的表/字段名，表名可以限定 schema 或 database。升级前核对依赖非标准 SQL 标识符的规则并映射到合法名称。

七个调整模块均通过 `go test -race`、`go vet`。真实服务验证仅使用本机隔离 PostgreSQL 和 Mosquitto。TDengine SQL 和资源验证使用替身连接，真实服务升级前需进行小流量回读验证。制品由 `build-plugins.sh` 生成并保留独立版本、摘要、SBOM 和清单。

后续建议优先将三个数据库 Sink 的按表内存队列纳入总量限制。需要跨重启取证的规则可采用持久缓冲和明确的业务提交回执，当前 Sink 的定时批量属于内存暂存。针对 MQTT 旧轮询绑定应规划独立的释放和超时协议，并补齐真实 EMQX、TLS、QoS2、72 小时长稳以及不同 PLC/CNC、ARM 真机的验收矩阵。

全量验证日志位于本机审计目录的 `plugins/all-modules.log`，覆盖 119 个普通模块、FANUC 原生连接器合成 ABI 夹具及 `fanucutil` 辅助模块。7 个更新插件均生成 Linux amd64/arm64 本地独立压缩包，核对 14 个包的架构、制品和 SBOM 摘要、每包的单插件清单。arm64 结果为编译验证，发布签名和生产升级另行校验。

七个变更模块的可达依赖扫描均无发现。`connect-tdengine` 另外将间接依赖 Gorilla WebSocket 由 1.5.0 升为 1.5.3，消除扫描中发现的包级告警，升级后复扫无发现。告警及修复版本可查 [Go 官方漏洞条目 GO-2026-6278](https://pkg.go.dev/vuln/GO-2026-6278)。
