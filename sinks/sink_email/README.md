# sink-email

Input body is a configured payload string (default rendered, e.g. render-template output). Resource owns sender/auth; To/Subject are static Sink configuration. Bounded per-instance alert quota and duplicate claim cache; event.id is default key, optional dedup_path groups an alarm identity. Claims occur before network submission; failed/unknown attempts remain claimed until TTL rather than being blindly retried. Accepted replay may re-ACK without resending. This cache is volatile: use persistent command-guard/business outbox upstream for restart policy, and recognize physical SMTP exactly-once is not guaranteed. Stable Message-ID does not force mailbox deduplication. ack_smtp_receipt is false by default; enabling it chooses SMTP acceptance, not delivery/read/business confirmation. No email was sent outside loopback tests.
